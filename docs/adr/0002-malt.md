# ADR 0002 — Missions Malt : suivre, ne pas refacturer

**Statut** : accepté · **Date** : 2026-11-03

## Contexte
Sur Malt, la plateforme émet la facture au nom du freelance (mandat de facturation), encaisse le client et verse le
net après ses frais de service (taux HT variable selon la relation client, TVA 20 % en sus). Malt n'expose pas d'API
publique côté freelance pour lire missions et factures.

## Décision
- Le **canal** (`MALT` / `DIRECT`) est porté par le client et copié sur chaque devis et facture.
- Facture Malt : pas de numéro `F-…` (il casserait la séquence légale avec des factures que l'on n'émet pas soi-même) ;
  le numéro Malt est saisi dans `external_ref`. Pas de relance Brevo : c'est Malt qui recouvre.
- Frais : `malt_fee_bps` réglable par client (défaut dans les Paramètres), **figé** sur la facture à sa création.
- Trésorerie : revenu = montant facturé, dépense = frais TTC → le net égale le virement, le CA reste le brut.
- Pas de scraping de Malt : saisie manuelle des prospects (lien vers la mission conservé).

## Conséquences
Si Malt ouvre une API freelance, une intégration pourra créer les opportunités et rapprocher les versements
automatiquement, sans changer le modèle.
